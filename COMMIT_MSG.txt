Promote the plugin to the repository root so `dsh plugin add` works

A DSH marketplace entry points at a GitHub repository, and the installer reads
`package.json` from that repository root. The plugin used to live under
`vendor/dsh-multisim-toolkit/`, which meant the root described a skill but not
an installable bundle, so the repo could not be added by URL at all.

Move the bundle (package.json, cordis.patch.yml, index.js, lib/, worker/,
locale/, icon.svg) to the root and keep the skill beside it:

- PLUGIN.md  the former plugin README, now the plugin-body document
- README.md  rewritten as one overview covering both the plugin and the skill
- package.json  drop "private", add repository/homepage/bugs/author/license/
                keywords, point "files" at the new layout
- scripts/install.ps1  bundle root prefers <repo>, falls back to the old
                       vendor path; still ASCII-only for Windows PowerShell 5.1
- scripts/selfcheck.py  worker dir found via _find_worker_dir(), same fallback
- LICENSE  blast.c paths lose the vendor/ prefix

`dsh.bundle.patch` is unchanged, so the installed entry id stays
`include:multisim-toolkit`.

Verified: node --check on index.js and lib/worker.js; py_compile on all seven
worker modules; install.ps1 -Action check all green against the new root;
selfcheck.py --design 设计3.ms14 decodes 618589 bytes in one block and lists
7 components; reinstall from the repo root reports the new link path and
msim_status resolves worker script to <repo>/worker/msim_worker.py.
